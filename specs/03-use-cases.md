# 用例模型文本

## 1. 参与者

- **Reader**：所有读者的通用参与者，可注册、查询、预约和查询本人借阅。
- **StudentReader**：Reader 的学生分类，按学生借阅策略执行。
- **TeacherReader**：Reader 的教师分类，按教师借阅策略执行。
- **Librarian**：图书管理员，代理借书、还书并协助查询。
- **SystemAdmin**：系统管理员，维护证件、管理员、目录、副本和规则。
- **系统时钟/预约调度（外部时间源）**：提供到期判断和预约队列状态推进所需的当前时间；不承担人工业务决策。

## 3. UC-001 注册读者账号

**主要参与者**：Reader  
**次要参与者**：无  
**前置条件**：读者尚未存在重复账号；注册入口可用。  
**后置条件**：创建读者实体，状态为未办证或可办证；不创建借阅记录。

**基本事件流**：

1. Reader 提交姓名、院系/单位、联系方式和读者类型。
2. 系统校验必填字段、格式和唯一身份信息。
3. 系统创建 `Reader` 及其读者分类。
4. 系统返回读者 ID 和办证提示。

**备选事件流**：

- A1：读者已存在但未办证，系统提示使用现有账号办理借阅证。
- A2：可选联系方式缺失但不影响唯一识别时，系统允许保存并标记待补充。

**异常事件流**：

- E1：必填字段非法或身份重复，拒绝创建并指出原因。
- E2：持久化失败，回滚账号创建并返回可重试错误。

**关联需求**：FR-001、BR-001。

## 4. UC-002 办理借阅证

**主要参与者**：SystemAdmin  
**次要参与者**：Reader  
**前置条件**：读者账号存在且未拥有有效借阅证；系统管理员身份有效。  
**后置条件**：创建有效 `BorrowCard`，与 Reader 一对一关联。

**基本事件流**：

1. SystemAdmin 输入或选择读者 ID。
2. 系统显示读者姓名、院系/单位和读者类型。
3. 系统验证读者存在且没有有效借阅证。
4. 系统按生成策略生成唯一卡号，写入姓名、院系/单位、状态和有效期。
5. 系统保存借阅证并返回卡号。

**备选事件流**：

- A1：读者已有停用证，管理员在确认无活动借阅、预约和未结罚款后重新激活或新建证件。

**异常事件流**：

- E1：读者不存在，拒绝办证。
- E2：已存在有效证件，拒绝重复办证。
- E3：卡号冲突时重新生成或失败重试，不得覆盖其他读者证件。

**关联需求**：FR-002、BR-001。

## 5. UC-003 删除或停用借阅证

**主要参与者**：SystemAdmin  ️
**次要参与者**：Reader、借阅/预约记录  
**前置条件**：借阅证存在且管理员有维护权限。  
**后置条件**：无活动关联时证件停用/删除；有活动关联时保留历史并返回阻断原因。

**基本事件流**：

1. 管理员选择借阅证并请求停用或删除。
2. 系统检查未归还借阅、有效预约和未结罚款。
3. 无阻断关联时更新证件状态并记录操作人。
4. 系统返回结果。

**备选事件流**：

- A1：存在历史但无活动关联，允许逻辑删除并保留历史查询能力。

**异常事件流**：

- E1：存在未归还、有效预约或未结罚款，拒绝物理删除并提示先处理关联。
- E2：非系统管理员操作，返回权限错误。

**关联需求**：FR-003、BR-009、BR-010。

## 6. UC-004 添加图书管理员

**主要参与者**：SystemAdmin  ️
**次要参与者**：Librarian  
**前置条件**：管理员身份有效；标识未被占用。  
**后置条件**：创建可用的图书管理员账户。

**基本事件流**：提交资料 -> 校验唯一性 -> 创建账户并赋予 Librarian 角色 -> 返回结果。

**备选事件流**：恢复既有停用账户；若该账户是最后一个有效系统管理员，则拒绝停用并提示必须保留管理入口。

**异常事件流**：资料不完整、标识重复或权限不足时拒绝。

**关联需求**：FR-004、BR-010。

## 7. UC-005 删除图书管理员

**主要参与者**：SystemAdmin  ️
**次要参与者**：Librarian、历史借阅记录  
**前置条件**：目标图书管理员存在。  
**后置条件**：账户停用，历史经办记录保留。

**基本事件流**：选择管理员 -> 检查目标 -> 停用账户 -> 写入审计记录。

**备选事件流**：已停用账户重复操作时返回幂等结果。

**异常事件流**：目标不存在或操作者非系统管理员时拒绝。

**关联需求**：FR-005、BR-010。

## 8. UC-006/007 维护图书标题信息

**主要参与者**：SystemAdmin  ️
**次要参与者**：Reader、馆藏副本  
**前置条件**：管理员有目录维护权限。

**基本事件流**：管理员提交标题元数据 -> 系统校验标准号和借出物类型 -> 创建、更新或停用标题 -> 返回目录状态。

**备选事件流**：标题已有历史记录时转为停用而非物理删除。

**异常事件流**：重复标准号、存在活动副本时删除请求被拒绝；非法类型被拒绝。

**后置条件**：有效标题可检索；停用标题不可新增借阅。

**关联需求**：FR-006、FR-007、BR-009。

## 9. UC-008/009 维护馆藏副本

**主要参与者**：SystemAdmin  ️
**次要参与者**：BookTitle、Loan  
**前置条件**：标题有效；管理员有馆藏维护权限。

**基本事件流**：提交标题和条码 -> 校验条码唯一、馆藏归属和可借属性 -> 创建或停用副本 -> 更新查询索引。

**备选事件流**：有历史借阅的副本转为停用并保留条码，不做物理删除。

**异常事件流**：重复条码、无效标题、有效借阅中的副本删除请求被拒绝。

**后置条件**：副本状态可借、已借出、预约保留或停用之一，且状态转换合法。

**关联需求**：FR-008、FR-009、BR-005、BR-009。

## 10. UC-010 查询图书

**主要参与者**：Reader、Librarian、SystemAdmin  ️
**次要参与者**：Catalog  
**前置条件**：调用者身份及查询权限有效。

**基本事件流**：输入标题/作者/标准号/类型/状态条件 -> 系统检索标题和副本 -> 返回摘要、可借状态和可预约状态。

**备选事件流**：条件为空时返回分页目录；无匹配时返回空列表。

**异常事件流**：非法查询条件或调用者无权限时返回参数/权限错误。

**后置条件**：不改变领域状态。

**关联需求**：FR-010。

## 11. UC-011 办理借书（重点用例）

**主要参与者**：Librarian  ️
**次要参与者**：Reader、BorrowCard、BorrowPolicy、LibraryItem、Loan、系统时钟  
**前置条件**：图书管理员账户有效；借阅证号和馆藏副本可被检索；借书事务可用。

**后置条件**：成功时新增一条状态为 `BORROWED` 的 Loan，副本状态为 `ON_LOAN`，读者有效借阅数增加，到期日和规则快照已保存；失败时所有变更回滚。

**基本事件流**：

1. 图书管理员输入借阅证号。
2. 系统验证借阅证是否存在、状态是否有效且未过期。
3. 系统读取读者类型和 `BorrowPolicy`，检查读者当前有效借阅数是否超过上限。
4. 系统检查读者是否存在超期未归还图书。
5. 校验通过后，系统向图书管理员显示读者姓名、读者类型和当前借阅摘要。
6. 图书管理员输入图书副本条码或馆藏信息。
7. 系统验证副本属于本馆、标题有效、资源可借且当前未被占用。
8. 系统根据读者策略计算应还日期，创建 Loan，记录管理员、借出时间和规则快照。
9. 系统在同一事务中更新副本状态为已借出、读者借阅计数，并返回借阅单据。

**备选事件流**：

- A1：副本当前不可借但标题可预约，系统提示读者转入 UC-014。
- A2：读者达到上限但管理员输入多个副本，系统在第一个违规副本处停止，已处理部分整体回滚。
- A3：规则在请求期间切换版本，事务锁定本次采用的有效版本并保存快照。

**异常事件流**：

- E1：借阅证不存在、停用或过期，拒绝借书。
- E2：读者超过借阅数量，拒绝借书。
- E3：存在超期未还图书，拒绝借书。
- E4：副本非本馆、条码不存在、已借出、停用或标题失效，拒绝借书。
- E5：并发请求已锁定副本，返回资源冲突，不能创建第二条有效 Loan。
- E6：任一持久化步骤失败，事务回滚并记录错误。

**关联需求**：FR-011、BR-001、BR-002、BR-003、BR-004、BR-006、BR-012。

## 12. UC-012 办理还书（重点用例）

**主要参与者**：Librarian  ️
**次要参与者**：Reader、LibraryItem、Loan、FineRule、FineRecord、Reservation  
**前置条件**：图书管理员账户有效；可提供副本条码或借阅记录线索；还书事务可用。

**后置条件**：成功时 Loan 状态为 `RETURNED`，副本回到可借或预约保留状态，归还时间和经办人已保存；如超期则产生 FineRecord。

**基本事件流**：

1. 图书管理员输入副本条码（必要时补充借阅证号）。
2. 系统验证条码属于本馆且存在未结清 Loan。
3. 系统读取应还日期和实际归还时间，确定是否超期。
4. 系统按借出物类型选择 FineRule，计算罚款并生成/更新 FineRecord。
5. 系统将 Loan 标记为 `RETURNED`，记录归还时间、经办管理员和罚款关联。
6. 系统检查该标题的预约队列；有队列时将副本标记为预约保留，否则标记为可借。
7. 系统返回归还结果、罚款金额和预约分配提示。

**备选事件流**：

- A1：未超期，罚款为零，副本直接进入可借或预约分配。
- A2：有预约队列，副本暂不对普通查询显示为可借，队首预约进入可领取状态。
- A3：归还当天不额外计入超期天数，按自然日差值计算 `max(0, return_date - due_date)`。

**异常事件流**：

- E1：条码不是本馆馆藏，拒绝入库并提示转交外馆处理。
- E2：找不到未结清 Loan 或 Loan 已归还，拒绝重复归还。
- E3：FineRule 缺失或版本无效，事务回滚并进入人工处理队列，不得静默丢失归还。
- E4：更新副本或记录失败，整个还书事务回滚。

**关联需求**：FR-012、FR-015、BR-005、BR-007、BR-008、BR-012。

## 13. UC-013 查询借阅信息

**主要参与者**：Reader、Librarian、SystemAdmin  ️
**次要参与者**：Loan、FineRecord  
**前置条件**：调用者身份有效；查询范围符合角色权限。

**基本事件流**：调用者输入筛选条件 -> 系统执行授权范围过滤 -> 返回当前/历史 Loan、到期日、状态和罚款摘要。

**备选事件流**：读者不提供条件时默认查询本人当前借阅；管理员可分页查询。

**异常事件流**：越权查看其他读者记录时拒绝；非法筛选条件返回参数错误。

**后置条件**：不改变领域状态。

**关联需求**：FR-013、NFR-002。

## 14. UC-014 预约图书（重点用例）

**主要参与者**：Reader  ️
**次要参与者**：BorrowCard、BookTitle、LibraryItem、Reservation、系统时钟  
**前置条件**：读者有有效借阅证；标题有效且当前无可直接借副本或允许排队预约。

**后置条件**：创建状态为 `WAITING` 的预约，包含读者、标题、创建时间和队列序号；不得产生重复有效预约。

**基本事件流**：

1. Reader 通过网络选择标题并提交预约。
2. 系统验证借阅证有效、标题未停用、读者未重复预约且有效预约数不超过 5 个。
3. 系统读取该标题当前预约队列并按创建时间分配下一序号。
4. 系统创建 Reservation 并返回队列位置。
5. 副本归还时，系统按队首规则将其标记为预约保留并通知/展示领取状态。

**备选事件流**：

- A1：存在可借副本时，系统提示直接借阅，不创建预约。
- A2：队首读者取消或在 3 个自然日内未领取，系统取消本次保留并将副本分配给下一位。

**异常事件流**：

- E1：借阅证无效、标题停用或超过预约上限，拒绝预约。
- E2：同一读者已有有效预约，返回原预约位置而不重复创建。
- E3：并发预约同一标题时，系统以事务顺序分配唯一队列序号。

**关联需求**：FR-014、BR-001、BR-008。

## 15. UC-015 计算超期罚款（重点用例）

**主要参与者**：系统内部/图书管理员触发  ️
**次要参与者**：FineRule、Loan、FineRecord、系统时钟  
**前置条件**：存在 Loan；借出物类型有有效 FineRule。

**后置条件**：产生可追溯 FineRecord，包含超期天数、费率、封顶值、规则版本和计算结果。

**基本事件流**：读取应还日期和归还日期 -> 按自然日计算超期天数 -> 按借出物类型选择规则（中文图书 0.50 元/日封顶 100 元、外文图书 1.00 元/日封顶 200 元、中文杂志 1.00 元/日封顶 100 元、外文杂志 2.00 元/日封顶 200 元、论文 2.00 元/日封顶 300 元）-> 应用费率和封顶 -> 保存罚款记录。

**备选事件流**：未超期时保存零金额结果；规则更新后已借 Loan 使用原规则快照。

**异常事件流**：缺少规则、日期非法或结果溢出时拒绝结算并返回人工处理原因。

**关联需求**：FR-015、BR-007、BR-011。

## 16. UC-016 维护借阅规则和罚款规则

**主要参与者**：SystemAdmin  ️
**次要参与者**：BorrowPolicy、FineRule、Reader、LibraryItem  
**前置条件**：系统管理员身份有效；规则版本管理可用。

**后置条件**：新规则按生效时间启用，既有 Loan 的快照不变。

**基本事件流**：管理员选择规则类型 -> 输入读者类型/借出物类型、上限/期限或费率/封顶 -> 校验范围与生效期 -> 保存新版本 -> 返回规则状态。系统管理员还可对罚款执行减免或作废，但必须填写原因并写入审计记录。

**备选事件流**：停用未来规则并保留历史版本；查询规则版本和生效范围。

**异常事件流**：费率为负、上限为零、同类生效期重叠、最后一个系统管理员被停用或非系统管理员操作时拒绝。

**关联需求**：FR-016、BR-006、BR-007、BR-010、BR-011。

## 17. 用例关系与覆盖说明

- UC-011 **include**“验证借阅证”、**include**“检查借阅策略”、**include**“检查副本可借状态”。
- UC-012 **include**“验证本馆副本与未结清 Loan”、**include** UC-015；预约队列分配为归还后的条件扩展。
- UC-014 **include**“验证借阅证和标题状态”，副本归还后的队列分配由预约策略扩展。
- UC-002/003、UC-004/005、UC-006/007、UC-008/009 分别构成维护操作的新增/停用或删除变体。
- StudentReader 和 TeacherReader 泛化自 Reader；具体学生层级通过读者类型与 `BorrowPolicy` 区分，避免无业务行为的类爆炸。
