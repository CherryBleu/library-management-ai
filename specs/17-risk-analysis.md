# 风险分析

| 风险 | 影响 | 可能性 | 缓解措施 | 验证方式 |
| --- | --- | --- | --- | --- |
| 需求规则被误解 | 借阅上限、期限或罚款实现错误 | 中 | 固化 Q01-Q28 决定并维护 FR/BR 追踪 | 需求审查 |
| 用例遗漏异常流 | 借书或还书出现部分更新 | 中 | 为核心用例明确失败路径和事务回滚 | 用例审查与集成测试 |
| UML 与文字规格漂移 | 模型无法作为实现依据 | 中 | 每次修改同步检查元素、关系和编号 | PlantUML 渲染与交叉检查 |
| 领域模型机械映射数据库 | 业务规则散落在表或 Controller | 中 | 使用 BorrowPolicy/FineRule 策略和领域服务 | 领域模型审查 |
| 并发借阅同一副本 | 产生重复有效 Loan | 高 | 事务锁和部分唯一索引 | 并发集成测试 |
| 预约队列错序或长期占用 | 读者权益不一致 | 中 | queue_no 唯一、3 日保留、超时转移 | 队列测试 |
| 历史数据被删除 | 无法审计借还和罚款 | 中 | 逻辑删除、外键和审计日志 | 数据库约束检查 |
| 权限越权 | 管理数据或罚款被非法修改 | 中 | 应用服务授权、角色隔离、错误码审计 | 权限测试 |
| 罚款规则版本漂移 | 已发生借阅被错误重算 | 中 | Loan 保存 policy/fine rule 快照 | 版本回归测试 |
| Agent 生成内容不完整 | 规格遗漏或虚构 | 中 | 六阶段 AI 日志、人工审查清单、逐文档提交 | Git diff 审查 |
| PlantUML 工具缺失 | 图形布局问题未及时发现 | 中 | 先做文本起止和关系检查，提交前用渲染器复核 | PlantUML 渲染 |
| 技术选型过早 | 实验二实现返工 | 低 | 实验一只冻结 Java 17/关系库/REST 约束，框架后定 | 架构审查 |

## 风险接受条件

实验一只有在需求、用例、领域、架构、数据库和审查清单均有人工作证后建立 baseline。未安装 PlantUML 或尚无可执行源码时，相关风险必须保留为后续实验二任务，不得伪造测试通过。
