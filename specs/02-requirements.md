# 需求规格说明书

## 1. 文档目的与范围

本文档将 `00-project-brief.md` 的业务目标转换为可验证的功能需求、非功能需求和业务规则，作为实验一后续用例、领域模型和架构设计的基线。业务决策已在 `01-clarifying-questions.md` 中确认。

## 2. 系统目标

系统为学校图书馆提供读者、借阅证、图书目录、馆藏副本、借阅、预约和罚款管理能力。图书管理员代理流通操作，系统管理员维护基础资料和规则，读者通过网络进行注册、查询和预约。

## 3. 参与者

| 参与者 | 责任/权限摘要 |
| --- | --- |
| Reader | 注册账号、查询图书、预约图书、查询本人借阅信息 |
| StudentReader | Reader 的学生分类，使用对应学生 `BorrowPolicy` |
| TeacherReader | Reader 的教师分类，使用教师 `BorrowPolicy` |
| Librarian | 代理办理借书、还书；查询流通信息 |
| SystemAdmin | 借阅证、管理员、标题、副本、借阅规则和罚款规则维护 |

本阶段不实现真实登录认证；接口使用操作人 ID 表示已认证身份。

## 4. 功能需求

### FR-001 注册读者账号

系统应允许读者提交姓名、院系或单位、联系方式和读者类型，创建唯一读者账号，并以“未办证/可办证”状态保存。

**验收标准**：

- 给出完整且合法资料时，系统创建一个唯一 `reader_id`，读者状态可查询。
- 缺少姓名、读者类型或重复的唯一身份信息时，系统拒绝注册并返回字段级错误。
- 注册不得自动产生借阅记录或馆藏副本。

### FR-002 办理借阅证

系统管理员应能为已注册读者办理借阅证。借阅证至少包含读者姓名、院系或单位、唯一借阅证号、状态和有效期。

**验收标准**：

- 为无有效借阅证的读者办理成功，产生唯一 `card_no` 并与读者关联。
- 读者已有有效借阅证或不存在时，操作失败且不产生重复证件。
- 借阅证号采用 `CARD+四位年份+6位序号` 格式；完整号码全局唯一，历史号码跨年份不复用。

### FR-003 删除或停用借阅证

系统管理员应能停用借阅证；存在未归还借阅、有效预约或未结罚款时，系统应按配置禁止物理删除并保留历史关联。

**验收标准**：

- 无活动关联时，证件可转为停用/删除状态，历史借阅数据仍可追溯。
- 存在活动关联时，系统拒绝物理删除并说明阻断原因。
- 停用证件不能发起新的借书或预约。

### FR-004 添加图书管理员

系统管理员应能创建图书管理员账户并赋予 `Librarian` 角色。

**验收标准**：

- 输入唯一管理员标识和合法资料后，账户创建成功且角色为图书管理员。
- 标识重复或缺少必填资料时，操作失败。
- 图书管理员不能因此获得系统管理员权限。

### FR-005 删除图书管理员

系统管理员应能停用图书管理员账户并保留其历史经办记录。

**验收标准**：

- 停用后该管理员不能办理新的借书或还书。
- 历史借阅记录仍保留经办人标识。
- 删除最后一个系统管理员不被允许，避免系统失去管理入口。

### FR-006 添加图书标题信息

系统管理员应能维护标题、作者、ISBN/标准号、出版社、语言和借出物类型等书目元数据。

**验收标准**：

- 合法且唯一的标题信息保存成功并可检索。
- 缺少标题或借出物类型时拒绝保存。
- 有历史借阅关联的标题不得被物理删除。

### FR-007 删除图书标题信息

系统管理员应能删除无历史关联的标题，或将有历史关联的标题标记为停用。

**验收标准**：

- 无馆藏副本和历史记录时可删除。
- 有副本或历史记录时拒绝物理删除，并提供停用结果。
- 停用标题不可新增副本或产生新借阅。

### FR-008 添加馆藏副本

系统管理员应能为有效标题添加馆藏副本，记录唯一条码、馆藏位置、借出物类型和可借状态。

**验收标准**：

- 条码唯一且标题有效时，副本创建成功并初始状态为可借或配置状态。
- 重复条码、无效标题或不允许借出的资源类型导致操作失败。
- 新副本可在图书查询结果中按状态显示。

### FR-009 删除馆藏副本

系统管理员应能删除无历史关联的副本，或停用已有借阅历史的副本。

**验收标准**：

- 有效借阅中的副本不能删除或停用，直到借阅结清。
- 停用副本不能再次借出或被分配新预约。
- 历史借阅中的副本标识和条码仍可追溯。

### FR-010 查询图书

读者、图书管理员和系统管理员应能按标题、作者、标准号、语言、借出物类型和可借状态查询书目及副本摘要。

**验收标准**：

- 合法查询返回匹配标题及每个副本的当前状态。
- 无匹配结果返回空结果而非错误。
- 查询不得泄露不属于调用者权限范围的管理数据。

### FR-011 办理借书

图书管理员应代理读者借书。系统必须验证借阅证、读者借阅上限、超期未还记录和副本馆藏/可借状态，然后创建借阅记录并更新副本状态。

**验收标准**：

- 有效证件、未超上限、无超期未还且副本可借时，产生一条有效 `Loan`，副本变为已借出，并计算到期日。
- 无效/停用证件、超过数量、有超期未还、副本非本馆或不可借时，操作拒绝且数据不发生部分更新。
- 每次借书记录经办图书管理员和采用的借阅规则快照。

### FR-012 办理还书

图书管理员应代理读者归还副本。系统必须确认副本属于本馆并存在未结清借阅，更新借阅和副本状态，并按规则计算超期罚款。

**验收标准**：

- 找到有效借阅且副本属于本馆时，借阅状态变为已归还，归还时间和经办人被记录。
- 非本馆条码或不存在有效借阅记录时，操作拒绝且不创建虚假归还。
- 超期时创建或更新 `FineRecord`，未超期时罚款为零；预约队列按规则获得后续分配机会。

### FR-013 查询借阅信息

读者可查询本人当前和历史借阅、到期日及罚款摘要；图书管理员和系统管理员可按权限查询更大范围记录。

**验收标准**：

- 读者查询只返回本人记录。
- 管理角色可按读者、证件、条码和状态筛选授权范围内记录。
- 结果能区分借出、已归还和超期状态。

### FR-014 预约图书

读者应能对无可借副本的有效标题提交网络预约。系统按创建时间形成队列，并防止同一读者对同一标题重复有效预约。

**验收标准**：

- 有效借阅证且标题可预约时，系统创建带队列序号的 `Reservation`。
- 停用证件、停用标题、已有同标题有效预约或超出预约上限时，操作拒绝。
- 副本可用后，系统按队首顺序标记可领取/分配状态，并为队首读者保留 3 个自然日。

### FR-015 计算超期罚款

系统应根据借出物类型对应的 `FineRule`、应还日期和实际归还日期计算罚款，并生成可追溯的 `FineRecord`。

**验收标准**：

- 未超期记录的罚款为零。
- 超期记录按自然日超期天数、费率和封顶金额计算，结果可重复计算；基线费率为中文图书 0.50 元/日封顶 100 元、外文图书 1.00 元/日封顶 200 元、中文杂志 1.00 元/日封顶 100 元、外文杂志 2.00 元/日封顶 200 元、论文 2.00 元/日封顶 300 元。
- 规则版本、生效时间、计算输入和结果被保存，人工调整（若开放）必须记录原因。

### FR-016 维护借阅规则和罚款规则

系统管理员应能新增、修改、启停和查询 `BorrowPolicy` 与 `FineRule`，并为未来借阅保留生效时间和版本。

**验收标准**：

- 借阅规则可按读者类型配置最大借阅数和借阅期限。
- 罚款规则可按借出物类型配置费率和封顶金额。
- 已产生的借阅记录继续使用借出时规则快照；无效范围、重叠生效期或非管理员操作应被拒绝。

## 5. 非功能需求

### NFR-001 一致性与事务

借书和还书必须在一个事务边界内完成资格校验、借阅变更、副本状态变更和罚款更新；失败时整体回滚。并发借阅同一副本时最多允许一条有效借阅。

### NFR-002 权限隔离

每个管理操作必须校验角色和资源范围。Controller 只负责请求校验、授权入口和响应映射，业务规则由应用服务、领域对象或策略执行。

### NFR-003 可追溯性

办证、借书、还书、预约、规则修改和权限失败应保留操作人、时间、目标对象和结果。记录不得因普通删除而丢失。

### NFR-004 可测试性

核心借书、还书、预约、罚款计算、借阅证状态和权限失败场景应能通过自动化单元或集成测试验证。

### NFR-005 可维护性

领域模型不应机械等同于数据库表；借阅和罚款变化应可通过策略替换，接口层与领域层通过 DTO 或应用服务隔离。

### NFR-006 性能基线

在课程实验规模下，常用条码、证件号和标题查询应使用索引；单次借还操作应返回明确成功或失败结果。后续实现采用 Java 17、关系数据库（优先 PostgreSQL）和 REST API，框架在实验二确定。

## 6. 业务规则

| 编号 | 规则 |
| --- | --- |
| BR-001 | 借阅证号必须唯一；只有有效借阅证可以借书和预约。 |
| BR-002 | 读者同时有效借阅数不得超过其 `BorrowPolicy` 上限。 |
| BR-003 | 读者存在超期未还图书时，不得办理新的借书。 |
| BR-004 | 借书必须由有效图书管理员代理完成。 |
| BR-005 | 还书必须验证副本属于本馆且存在未结清借阅。 |
| BR-006 | 不同读者类型使用不同最大借阅数和借阅期限。实验基线为本科生 5/30 天、研究生 10/60 天、博士生 15/90 天、专科生 5/30 天、教师 20/90 天。 |
| BR-007 | 不同借出物类型使用独立罚款规则；罚款按自然日超期天数计算并按已确认费率和封顶值结算。 |
| BR-008 | 预约按创建时间排队；同一读者对同一标题不得有多个有效预约，每名读者最多 5 个有效预约；队首保留 3 个自然日，超时转给下一位。 |
| BR-009 | 有历史借阅关联的标题、副本和借阅证不得物理删除，应采用停用或逻辑删除。 |
| BR-010 | 系统管理员负责规则和基础资料维护；图书管理员不得维护管理员账户或规则。 |
| BR-011 | 规则修改不得追溯改变已产生借阅的到期日和罚款计算依据；系统管理员可记录原因后减免或作废罚款。 |
| BR-012 | 借还操作失败时不得留下部分更新；并发请求不得重复占用同一副本。 |

`01-clarifying-questions.md` 中 Q01-Q28 已完成确认；本需求基线不再保留未决业务问题。后续新增变化必须通过独立变更任务更新受影响规格并重新人工审查。

## 8. 验收总览

实现或原型演示通过以下条件才可认为满足本需求基线：

1. 16 条功能需求均有可执行的验收场景和明确失败结果。
2. 借书、还书、预约、办证和罚款五个重点流程覆盖正常、备选和异常路径。
3. 借阅证唯一性、借阅上限、超期阻断、馆藏归属、预约排队和规则版本均可验证。
4. 角色权限和事务一致性测试通过。
