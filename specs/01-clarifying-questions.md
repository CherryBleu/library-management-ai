# 需求澄清问题

本文件用于在正式需求规格冻结前记录需要人类确认的业务和技术问题。问题按参与者、用例、规则、权限、数据、异常、架构、测试和教学复杂度分类。问题总数为 28 个，问题编号在后续规格中保持稳定。

## 一、参与者与目标

### Q01：第一阶段是否需要真实登录认证？

候选方案：A. 暂不实现，以 `reader_id`、`librarian_id`、`admin_id` 表示操作人；B. 实现账号密码和会话认证。

### Q02：读者、学生读者和教师读者的关系如何表达？

是否采用 `Reader` 基类及 `StudentReader`、`TeacherReader` 子类型？专科生、本科生、研究生和博士生是学生的枚举分类，还是独立子类？

是否必须由系统管理员审核并办理借阅证后才能借书和预约？

## 人类回答

以下决定作为实验一的需求基线，后续规格按此执行。决定由本次任务负责人代行人工澄清，确认日期为 2026-10-10。

### Q01：第一阶段是否需要真实登录认证？

- **决定**：采用 A。实验一不实现真实登录认证，接口使用 `reader_id`、`librarian_id` 或 `admin_id` 表示已认证操作人。
- **理由/来源**：实验一重点是需求、UML、领域和架构建模；避免把认证实现细节混入业务模型。
- **影响文件**：`02-requirements.md`、`03-use-cases.md`、`07-architecture.md`。
- **确认人/日期**：任务负责人 / 2026-10-10

### Q02：读者、学生读者和教师读者的关系如何表达？

- **决定**：使用 `Reader` 基类及 `StudentReader`、`TeacherReader` 子类型；专科生、本科生、研究生和博士生作为 `ReaderType`/学生层级枚举，不单独建类。
- **理由/来源**：保留业务上的读者分类，同时避免为只有配置差异的类型制造类层次。
- **影响文件**：`05-domain-model.md`、`06-domain-class-diagram.puml`、`13-database-design.md`。
- **确认人/日期**：任务负责人 / 2026-10-10

### Q03：读者注册后是否立即具有借阅资格？

- **决定**：不立即具有。注册成功后必须由系统管理员审核并办理有效借阅证，才可借书或预约。
- **理由/来源**：借阅证是实验一明确的业务对象和借阅资格边界。
- **影响文件**：`02-requirements.md`、`03-use-cases.md`、`05-domain-model.md`。
- **确认人/日期**：任务负责人 / 2026-10-10

### Q04：借书是否必须由图书管理员代理完成？

- **决定**：必须由有效图书管理员代理完成，第一阶段不提供读者自助借书。
- **理由/来源**：实验一原始要求明确图书管理员作为代理完成借还。
- **影响文件**：`02-requirements.md`、`03-use-cases.md`、`04-use-case-model.puml`。
- **确认人/日期**：任务负责人 / 2026-10-10

### Q05：还书是否需要出示借阅证？

- **决定**：不强制出示借阅证；图书管理员输入馆藏条码即可检索唯一未结清借阅，必要时用借阅证号辅助核对。
- **理由/来源**：还书的可靠主键是馆藏条码和有效 Loan，降低柜台操作负担。
- **影响文件**：`03-use-cases.md`、`07-architecture.md`、`13-database-design.md`。
- **确认人/日期**：任务负责人 / 2026-10-10

### Q06：借阅查询允许谁查看哪些数据？

- **决定**：读者只能查看本人记录；图书管理员可查看其业务范围内的流通记录；系统管理员可查看全部记录。
- **理由/来源**：遵循最小权限，并满足管理和审计需要。
- **影响文件**：`02-requirements.md`、`03-use-cases.md`、`07-architecture.md`。
- **确认人/日期**：任务负责人 / 2026-10-10

### Q07：删除借阅证前如何处理关联？

- **决定**：有未归还图书、有效预约或未结罚款时禁止物理删除；无活动关联时也采用停用/逻辑删除，历史记录始终保留。
- **理由/来源**：借阅证参与历史 Loan 和审计关联，不能破坏可追溯性。
- **影响文件**：`02-requirements.md`、`03-use-cases.md`、`05-domain-model.md`、`13-database-design.md`。
- **确认人/日期**：任务负责人 / 2026-10-10

### Q08：各读者类型的最大借阅数量是多少？

- **决定**：本科生 5 本、研究生 10 本、博士生 15 本、专科生 5 本、教师 20 本。
- **理由/来源**：采用实验一建议值，并将其作为可配置 `BorrowPolicy` 初始版本。
- **影响文件**：`02-requirements.md`、`05-domain-model.md`、`13-database-design.md`。
- **确认人/日期**：任务负责人 / 2026-10-10

### Q09：各读者类型的借阅期限是多少？

- **决定**：本科生 30 个自然日、研究生 60 个自然日、博士生 90 个自然日、专科生 30 个自然日、教师 90 个自然日；借出当天不计为完整借阅日，到期日为借出日期加期限天数。
- **理由/来源**：自然日规则容易验证，且与 `BorrowPolicy` 的期限字段一致。
- **影响文件**：`02-requirements.md`、`03-use-cases.md`、`05-domain-model.md`。
- **确认人/日期**：任务负责人 / 2026-10-10

### Q10：续借是否属于本阶段范围？

- **决定**：不属于实验一范围，也不生成续借用例；后续若加入，默认每笔一次、延长 30 天且存在有效预约时不得续借。
- **理由/来源**：原始实验要求未包含续借，先保持范围可控。
- **影响文件**：`00-project-brief.md`、`02-requirements.md`、`16-tasks.md`。
- **确认人/日期**：任务负责人 / 2026-10-10

### Q11：合订本、参考书和馆内阅览副本是否可借？

- **决定**：通过 `LibraryItem` 的借出资格和状态配置；参考书、合订本和馆内阅览副本默认 `REFERENCE_ONLY`/不可借，普通馆藏可借。
- **理由/来源**：同一书目可能包含不同借阅限制的副本，限制应落在副本而非标题上。
- **影响文件**：`02-requirements.md`、`05-domain-model.md`、`13-database-design.md`。
- **确认人/日期**：任务负责人 / 2026-10-10

### Q12：借出物类型如何映射到图书、杂志和论文？

- **决定**：`Book`、`Magazine`、`Thesis` 是 `LibraryItem` 子类型；中文/外文是语言属性，不另建类。罚款和可借规则按子类型及语言/馆藏配置选择。
- **理由/来源**：满足实验要求的继承关系，同时避免把语言维度硬编码进类型层次。
- **影响文件**：`05-domain-model.md`、`06-domain-class-diagram.puml`、`13-database-design.md`。
- **确认人/日期**：任务负责人 / 2026-10-10

### Q13：每种借出物类型的超期费率和封顶金额是多少？

- **决定**：中文图书 0.50 元/日、100 元封顶；外文图书 1.00 元/日、200 元封顶；中文杂志 1.00 元/日、100 元封顶；外文杂志 2.00 元/日、200 元封顶；论文 2.00 元/日、300 元封顶。按每件借阅记录计算。
- **理由/来源**：提供可执行、可测试的实验基线，规则仍通过 `FineRule` 配置而非写死在实体中。
- **影响文件**：`02-requirements.md`、`03-use-cases.md`、`05-domain-model.md`、`13-database-design.md`。
- **确认人/日期**：任务负责人 / 2026-10-10

### Q14：归还当天是否计入超期天数？

- **决定**：不计入额外超期天数；按本地自然日计算 `max(0, return_date - due_date)`，不采用营业日历。
- **理由/来源**：规则简单、可重复计算，适合课程实验和自动化测试。
- **影响文件**：`02-requirements.md`、`03-use-cases.md`、`05-domain-model.md`。
- **确认人/日期**：任务负责人 / 2026-10-10

### Q15：罚款是否允许减免、作废或人工调整？

- **决定**：允许系统管理员减免或作废；必须填写原因、操作人和时间，图书管理员无权调整金额。
- **理由/来源**：保留现实业务所需的纠错能力，同时通过权限和审计防止无记录修改。
- **影响文件**：`02-requirements.md`、`07-architecture.md`、`13-database-design.md`、`18-review-checklist.md`。
- **确认人/日期**：任务负责人 / 2026-10-10

### Q16：同一读者能否重复预约同一标题？

- **决定**：不能；同一读者对同一标题最多一个有效预约。同时最多 5 个有效预约。
- **理由/来源**：避免队列占位和重复通知，限制资源滥用。
- **影响文件**：`02-requirements.md`、`03-use-cases.md`、`05-domain-model.md`、`13-database-design.md`。
- **确认人/日期**：任务负责人 / 2026-10-10

### Q17：预约是否允许多人排队？

- **决定**：允许多人排队，严格按创建时间和唯一队列序号先到先得；取消后由后续预约顺次补位。
- **理由/来源**：实验要求明确网络预约，排队模型能表达多读者竞争同一标题。
- **影响文件**：`02-requirements.md`、`03-use-cases.md`、`05-domain-model.md`。
- **确认人/日期**：任务负责人 / 2026-10-10

### Q18：馆藏归还后如何分配给预约队列？

- **决定**：有队列时为队首读者保留 3 个自然日；超时未领取则取消该次保留并转给下一位。
- **理由/来源**：给出确定的可测试领取窗口，避免副本长期锁定。
- **影响文件**：`02-requirements.md`、`03-use-cases.md`、`05-domain-model.md`、`13-database-design.md`。
- **确认人/日期**：任务负责人 / 2026-10-10

### Q19：系统管理员和图书管理员的权限如何区分？

- **决定**：系统管理员维护借阅证、管理员、书目、副本、借阅策略和罚款规则；图书管理员仅代理借还和查询授权范围内流通记录。
- **理由/来源**：职责分离，符合实验一原始参与者定义。
- **影响文件**：`02-requirements.md`、`03-use-cases.md`、`07-architecture.md`、`08-package-diagram.puml`。
- **确认人/日期**：任务负责人 / 2026-10-10

### Q20：添加或删除管理员是否需要二次审核？

- **决定**：实验一不实现二次审核；系统管理员可直接维护，但禁止删除或停用最后一个有效系统管理员。
- **理由/来源**：避免引入额外审批工作流，同时保留系统可管理性的不变量。
- **影响文件**：`02-requirements.md`、`03-use-cases.md`、`05-domain-model.md`。
- **确认人/日期**：任务负责人 / 2026-10-10

### Q21：图书标题和馆藏副本删除采用什么方式？

- **决定**：无历史关联且无活动副本时允许物理删除；有历史关联时只能逻辑删除/停用；活动借阅中的副本不得删除。
- **理由/来源**：在数据清理和历史可追溯之间取平衡。
- **影响文件**：`02-requirements.md`、`03-use-cases.md`、`13-database-design.md`。
- **确认人/日期**：任务负责人 / 2026-10-10

### Q22：借阅证号如何生成？

- **决定**：格式为 `CARD` + 4 位年份 + 6 位序号；完整字符串全局唯一，序号按年份递增，跨年份不复用历史号码。
- **理由/来源**：可读且便于人工核验，同时满足借阅证唯一性。
- **影响文件**：`02-requirements.md`、`03-use-cases.md`、`13-database-design.md`。
- **确认人/日期**：任务负责人 / 2026-10-10

### Q23：图书副本条码如何生成并保证唯一？

- **决定**：实验一允许馆员录入已有条码；系统在保存时校验全局唯一。后续可增加系统生成，但不改变唯一约束。
- **理由/来源**：兼容真实馆藏已有条码，避免把编码设备纳入实验范围。
- **影响文件**：`02-requirements.md`、`03-use-cases.md`、`13-database-design.md`。
- **确认人/日期**：任务负责人 / 2026-10-10

### Q24：并发借阅同一副本时如何处理？

- **决定**：借阅操作在同一事务中锁定副本行并检查状态，最多产生一条有效 Loan；冲突请求返回资源已占用。
- **理由/来源**：保证馆藏状态和借阅记录一致。
- **影响文件**：`02-requirements.md`、`07-architecture.md`、`13-database-design.md`。
- **确认人/日期**：任务负责人 / 2026-10-10

### Q25：关键操作是否需要审计日志和可追溯错误码？

- **决定**：需要。办证、借书、还书、预约、规则修改、罚款调整和权限失败均记录操作人、时间、对象、结果和错误码。
- **理由/来源**：满足可追溯性和人工审查要求。
- **影响文件**：`02-requirements.md`、`07-architecture.md`、`13-database-design.md`、`17-risk-analysis.md`。
- **确认人/日期**：任务负责人 / 2026-10-10

- **决定**：实验一只冻结设计约束；后续实现采用 Java 17、关系数据库（优先 PostgreSQL）和 REST API，具体框架在实验二详细设计时确定。
- **理由/来源**：与实验一前置准备和提示词手册推荐工具一致，同时避免现在提前绑定框架。

- **确认人/日期**：任务负责人 / 2026-10-10
