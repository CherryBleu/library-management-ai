# Project Brief：图书管理系统

## 1. 项目背景

本项目是《软件设计与体系结构》课程实验一项目，用于训练需求分析、UML 建模、领域建模、分层架构设计和数据库概念设计能力。项目以 Agent 辅助的 Spec 驱动方式组织资料：先建立可审查的规格基线，再据此完成后续模型和实现。

## 2. 项目目标

开发一个面向学校图书馆的图书管理系统，支持读者注册、借阅证管理、图书目录与馆藏副本维护、借书、还书、借阅查询、网络预约和超期罚款计算。系统必须把借阅规则、借出物类型规则和角色权限表达为可验证的业务规则。

本阶段交付重点是需求规格、用例文本和领域模型；详细设计、编码和部署属于后续阶段。

## 3. 目标用户与参与者

- **读者（Reader）**：注册账号、查询图书、预约图书、查询自己的借阅信息。
- **学生读者（StudentReader）**：读者的一种分类，适用学生借阅规则。
- **教师读者（TeacherReader）**：读者的一种分类，适用教师借阅规则。
- **图书管理员（Librarian）**：作为代理为读者办理借书和还书，并协助查询借阅信息。
- **系统管理员（SystemAdmin）**：维护读者借阅证、管理员账户、图书标题、馆藏副本、借阅规则和罚款规则。

## 4. 主要业务

1. 注册读者账号并维护基本身份资料。
2. 为读者办理、停用或删除借阅证。
3. 维护图书标题信息及其馆藏副本。
4. 查询图书标题、馆藏状态和可预约状态。
5. 由图书管理员代理办理借书和还书。
6. 校验借阅证有效性、借阅上限、超期未还记录和馆藏归属。
7. 记录借阅、归还、超期和罚款信息。
8. 读者通过网络提交预约，系统按创建时间形成队列。
9. 系统管理员维护不同读者类型的借阅规则和不同借出物类型的罚款规则。

## 5. 读者类型与借阅规则（已确认基线）

| 读者类型 | 最大同时借阅数 | 默认借阅期限 |
| --- | ---: | ---: |
| 本科生 | 5 | 30 天 |
| 研究生 | 10 | 60 天 |
| 博士生 | 15 | 90 天 |
| 专科生 | 5 | 30 天 |
| 教师 | 20 | 90 天 |

系统通过 `BorrowPolicy` 保存规则，规则可按生效时间维护，借阅记录保存借出时采用的期限快照。

## 6. 借出物类型与罚款（已确认基线）

- 中文图书
- 外文图书
- 中文杂志
- 外文杂志
- 论文

不同借出物类型拥有独立的 `FineRule`。中文图书、外文图书、中文杂志、外文杂志、论文的费率/封顶分别为 0.50/100、1.00/200、1.00/100、2.00/200、2.00/300 元；按自然日超期天数计算，归还当天不额外计费。本阶段不接入真实支付。

## 7. 技术与建模要求

- 使用 Markdown 编写可审查的规格文档。
- UML 图使用 PlantUML 或 Mermaid 文本表达（由后续文件完成）。
- 采用分层架构和 MVC 思路，业务规则放在领域对象、策略或领域服务中，不放在 Controller。
- 读者、借阅证、借阅、预约和馆藏资源等核心概念应形成领域模型。
- Agent 生成内容必须经过人工审查，规格基线冻结后不得被实现任务擅自修改。
- 后续实现应配套自动化测试。

## 8. 范围边界

本实验一明确暂不实现以下内容：

- 真实登录认证、统一身份认证或微信登录；接口阶段可用操作人 ID 表示身份。
- 真实支付扣款。
- 条码扫描硬件集成。
- 复杂全文检索和推荐算法。
- 多校区馆藏调拨。
- 移动端原生应用和消息推送。

## 9. 可交付成果

本阶段至少交付：项目简报、需求澄清问题、需求规格、用例文本、领域模型，以及后续配套的 UML、架构、数据库、风险审查和 AI 使用记录文档。
